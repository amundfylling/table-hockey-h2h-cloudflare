## Backlog: confirmed findings without a plan yet

Ordered roughly by leverage. Each was checked against the code unless marked "unverified".

**Bugs**

- **A cancelled download fails every caller that shared it** (`public/js/data.js:63-80`). The
  in-flight request for a player file is tied to the first caller's abort signal; when that caller
  cancels, others who joined get an `AbortError` and show a false "could not load" error.
  `loadOpponentsForPlayer` already carries a workaround for exactly this (`data.js:437-441`).
  Effort M, risk MED (central loader).
- **The switcher popover reports its own cancel as an error** (`public/js/switcher.js:148-166`).
  `close()` aborts and then nulls the controller, so the catch block no longer recognises the
  abort. Effort S.
- **The tournament page hides everything when one array is missing**
  (`public/js/tournament-page.js:87,112,115,161-164,221-229`). Unchecked reads inside one
  try/catch. Effort S. Unverified whether the build can ever omit those keys.
- **Tournament page labels are not entity-decoded** where the server-side head is
  (`public/js/tournament-page.js:29,52,89,113,124,170` vs `functions/tournament.js:62`). Effort S.
- **Cross-source dedupe can drop Sportscorpion ids across a three-source chain**
  (`scripts/build_h2h.py:1132,1188`). Unverified; needs a three-source test with name and id
  columns before anyone changes it. Effort S, risk MED.
- **Supplemental rows with a blank or unknown `source` value count as Sportscorpion**
  (`scripts/build_h2h.py:512-520`). Latent: happens only if a scraper changes its `Source` column.
  A cheap guard is to fail when a supplemental file classifies as primary. Effort S.
- **Unparseable dates become undated rows without being counted**
  (`scripts/build_h2h.py:682`). `pd.to_datetime(..., errors="coerce")` with no format; nothing in
  `meta.json` reports how many dates were lost. Effort S. Impact unverified against real sources.
- **Placeholder accounts are not excluded from records** (`scripts/build_h2h.py:2325-2331`,
  records are built at line 2795 before `placeholder_player_ids` at 2802). Latent: the live
  `records.json` on 2026-11-09 contained none. Effort S.
- **Bracket label can differ between identical builds** (`scripts/tournaments.py:222-224`,
  iteration over a set of strings). Effort S.
- **Cached source files are not keyed by URL, only their validators are**
  (`scripts/build_h2h.py:2494-2499`, `scripts/download.py:76-78`). Affects local runs that switch
  override URLs; CI starts with an empty cache. Effort S.
- **Sitemap lists `part_of` fragment tournaments** that the tournaments list leaves out as
  duplicates (`scripts/build_h2h.py:2894` vs `scripts/tournaments.py:718`). Effort S.

## Direction: options for the maintainer

These are not ranked against the fixes above.

1. **Show data coverage on the site.** `meta.json` already publishes per-source accepted and
   rejected counts and latest dates; the footer only lists source names. `PRODUCT.md` asks for
   results that feel "fast and trustworthy". A small "data coverage" section would let a player
   who disputes a record see how complete each source is. Cheap, since the data already ships.
2. **Decide on offline use.** `manifest.webmanifest` declares `"display": "standalone"` but no
   service worker is registered, and `suggestions.md` item 2 (offline cache) is still open.
   Players checking records at a venue with poor Wi-Fi are the stated audience. The cost is cache
   invalidation: seven HTML files carry hand-bumped `?v=` strings, and the CSP needs `worker-src`.
   Worth a design spike before any build.
3. **Close or re-scope the embed idea.** `suggestions.md` item 10 proposes iframe embeds, but
   `public/_headers` sets `frame-ancestors 'none'` site-wide. Either mark it rejected or spike a
   dedicated `/embed` route with its own header rule.

## Findings considered and rejected

- **Year text placed in SVG markup without escaping** (`public/js/home.js:182`,
  `public/js/charts.js:282,556,606`): the values are 4-character year slices and the CSP allows
  only same-origin scripts. Defence in depth only; not worth a plan.
- **Glicko-2 volatility and RD steps differ from Glickman's paper** (`scripts/ratings.py:181-232`):
  the parameters were tuned by backtest against this exact code, so "fixing" it would move every
  rating for no measured gain. Worth one sentence on the ratings page or in the docstring, nothing
  more.
- **Sitemap is written outside the staged data tree** (`scripts/build_h2h.py:2888`): it lives in
  `public/`, not `public/data/`, by design; an interrupted write is replaced by the next build.
- **Trimming unused `export` keywords in `main.js` and `table.js`**: no behavior change, and the
  table comparators should stay exported for the tests suggested above.
- **Duplicated source-URL and env-flag parsing between `download.py` and `build_h2h.py`**: real,
  but small and stable; not worth the churn on its own.
- Items already recorded as accepted risks in `AUDIT.md` ("Known residual risks") were not
  re-reported: supplemental rows without ids, conservative dedupe, mutable upstream URLs in
  general, the single CI job holding deploy permission, in-memory payloads, plain-HTTP overrides,
  no committed end-to-end browser suite.
